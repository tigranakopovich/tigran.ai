## 2. Границы изменения

Изменять существующие исходники в prototypes/nimbus-preview: общие tokens/styles, раскладку компонентов и применение портрета. Three scene/shader менять только настолько, насколько необходимо для узнаваемой круглой Земли. Существующие data/motion controllers не переписывать ради нового дизайна. Допускается минимальное изменение DOM для раскладки с сохранением semantics, selectors и lifecycle. Обновлять generated HTML существующим способом, не править вручную minified dist.

Сохранить: пять смысловых блоков в четырёх визуальных областях; все якоря; точный основной copy; шесть/десять примеров; готовую последовательную печать; циклы около6/15s; вкладки и повтор активной; паузы/продолжение; progress15s; заполнение формы и существующий Telegram draft URL; fixed translucent header, меню и верхний прогресс прокрутки. Новые тексты, офферы, клиентские факты, страницы или взаимодействия не назначены.

Не менять root production, SPEC, зависимости/lockfile, маршрутизацию и настройки Lenis без отдельного необходимого исправления выявленного дефекта. Никаких install/update, commit/push, публикации, реальных сообщений. Факт чтения этого brief не разрешает deployment.

## 3. Единая система материалов

В существующем tokens.css централизовать палитру, убрать конкурирующие хаки/зелёные поверхности:
- общий фон #13171D;
- glass surface rgba(32,38,48,.72–.84);
- основной текст #F2F4F7;
- secondary/placeholder #B8C1CC;
- accent #92DABB, CTA text #10231D.

Мята используется для CTA, активного выбора, сигнала и статуса. Панели нейтральные, не зелёные. Серебристая граница1px rgba(225,235,245,.16–.24), радиус18–22px, деликатный верхний inset highlight и мягкая тень. Внутренние данные на чуть более плотном фоне. Не переносить самый яркий свет генератора буквально: материал должен быть спокойным и читаемым.

Локальный Manrope сохранить. Body16–18px, подписи12–14px, input≥16px. Обычный текст ≥4.5:1 на смешанной поверхности. Никаких полупрозрачных мелких серых текстов поверх точек. Blur8–12px допустим только на ограниченном числе крупных desktop surfaces; без вложенных фильтров и анимации blur/shadow. Mobile/coarse/fallback: blur0, более плотная заливка. Glass работает и без backdrop-filter.

Buttons: не менять размеры при hover; подъём максимум2–3px,160–220ms; pressed возврат, видимый keyboard focus, targets≥44px. Общее слабое свечение workspace — один наружный overlay, pointer-events:none, без внутренних прямоугольных краёв. Только fine pointer; touch/reduced статичны. Вне Hero никаких Земель и particle backgrounds.

## 4. Hero

Desktop: типографика слева, демонстрация справа; ориентир56/44 с gap40–56px, вычислять доли от оставшейся после gap ширины. H1 три строки: «Меньше рутины.» / «Больше времени» / «на бизнес.», третья мятная. Текст/CTA видны сразу. Не возвращать удалённый eyebrow. На высоком desktop законченный первый экран: min-block-size100svh border-box, heading задач ниже первого viewport; стрелка28–40px от нижнего края. При нехватке высоты естественный рост, без clipping.

Справа две содержательные стеклянные панели «ЗАДАЧА» → «РЕЗУЛЬТАТ», короткая связь только в зазоре. Уменьшить пустые резервы внутри; данные ближе к заголовкам. Панели стабильны при смене всех шести примеров, но не резервировать гигантскую высоту. Шесть вкладок и небольшая пауза; без плеера, previous/next и счётчика. Ритм/печать остаются рабочими около6s.

Земля — крупный читаемый фон именно правой демонстрации. Центр приблизительно совпадает с центром объединённого блока двух панелей; диаметр стартово около1.12–1.25 высоты этого блока, подбирать так, чтобы круг читался сверху и по бокам. Вся сцена не должна лезть под левый текст. Не сужать её до декоративного пятна. Узнаваемые серебристые континенты, тёмные океаны, мягкий край; без сетки/орбит/неона. Частицы частично видны через свободные области glass, но не мешают чтению.

Проекция строго круглая: одинаковые X/Y диаметры; camera aspect соответствует реальному canvas; никаких nonuniform CSS scale. Resize обновляет размеры/camera. Canvas pointer-events:none. Сохранять seeded позиции и число точек; континентальная маска вычисляется один раз из доступного подготовленного источника, а не на каждом кадре. Если источника географии нет, сообщить MAIN; остальной дизайн продолжить, не рисовать случайные острова как проверенную Землю. Движение через uniforms, очень медленное, без новой postprocessing цепочки.

Mobile: текст→CTA→компактная демонстрация→вкладки; локальная круглая Земля за демонстрацией, меньшая интенсивность. Естественная высота, а не уменьшенная desktop-картинка. Reduced/fallback — статичная сцена, полный текст и ручной выбор.

## 5. Задачи

Одна широкая glass панель, десять примеров внутри. Selector desktop двумя компактными рядами; explanation около28%, source→result около72%. Не превращать обратно в десять больших вертикальных карточек. Mini UI различаются содержимым: сообщение, таблица, документ, отчёт; точные данные из JSON, без гигантских пустых skeleton полос.

Сохранить около15s на демонстрацию и последовательное заполнение. Внизу тонкая дорожка процесса, «Повторить пример», маленькая остановка/продолжение; без transport player. Progress синхронен и при ручном запуске, сбрасывается на повтор, остаётся полным в конце. Общий cursor glow охватывает workspace, без видимого внутреннего прямоугольника. Нижний disclaimer сохраняется.

Mobile: heading→selectors→explanation→source→result→progress/controls. Естественная высота без внутренних скроллов, обрезки и пустого резерва. Не уменьшать шрифт ради одного экрана.

## 6. Подтверждённый кейс

Desktop copy/scene примерно43/57. Справа Telegram input и два независимых результата: материалы объявления и Google Sheets. Различать интерфейсы содержимым и иерархией, а не разными стилями. Точный HP840G7/артикул1 и немецкий текст из подготовленных файлов. Артикул один и тот же в объявлении и строке таблицы.

Оригинальных фотографий HP нет: не брать реалистичные ноутбуки из generated reference и не подменять чужой моделью. Сохранить честное существующее текстовое представление кейса; отсутствие материала отразить в отчёте. Не добавлять автопубликацию, цены, экономию времени, новые функции и фиктивные действия копирования/галереи.

Основной ряд выровнен по началу; раскрываемые «Материалы кейса» отдельным полным рядом под ним. При toggle основная схема/текст не уплывают вверх/вниз из-за центрирования. Никакого scrollIntoView. Полные данные доступны touch/keyboard; сохранить фокус и действующие controls. Mobile copy→input→materials→Sheets. Однократное проявление связей/результатов, содержимое доступно сразу.

Одна поверхность: три компактных этапа→результат разбора и условия→тонкий divider→портрет и контакт. Не возвращать мини-схемы этапов, техническую цепочку сервисов, дополнительный work canvas или «Повторить этапы». Иконки: разбор/инструмент/щит с галочкой; никаких людей, создающих впечатление команды.

Wide desktop: ориентир общей panel760–820px, padding24–32px; H2 этапов34–38px, одна строка только если помещается. После divider24–28px; контакт заметнее этапов благодаря иерархии заголовка/CTA, без огромной пустоты. Короткие desktop и mobile растут естественно, не фиксировать height и не скрывать copy.

Портрет импортировать из Avatar-graphite-shirt-v1.png отдельным asset, оптимизировать существующими средствами; не включать14MB original и не вырезать из mockup. Не генерировать/перекрашивать заново, не использовать CSS tint. Desktop старт128–144px шириной, mobile88px; сохранить пропорции, фокус на лице, без обрезки волос/подбородка. Alt «Тигран», без hover zoom.

Primary Conversion строго дословно SPEC, включая текущую подпись кнопки и оба шаблона сообщения. Поле56px desktop/52mobile минимум, font16px. ## 8. Сохранить инженерные правила Nimbus

Существующие Vite/vanilla/Three/GSAP/Lenis, lockfile и модули сохраняются. Один общий GSAP ticker, Lenis autoRaf:false; WebGL lazy и отдельно от формы/меню. Initial reduced не загружает GPU chunk. Immutable seeded geometry, движение uniforms; desktop DPR≤1.5/mobile≤1, mobile cap30. Renderer останавливается вне Hero/hidden. Не добавлять постоянный RAF, allocations и layout reads каждый кадр. BFCache suspension/restoration и normal cleanup сохранить.

No WebGL/load/context failure — статичный fallback и рабочий контент. Полный семантический текст остаётся в HTML, никаких live announcements печати букв. Не создавать дополнительные таймеры для уже работающих сценариев. Естественная прокрутка, текущая Lenis-плавность; никаких snap/pin/scroll hijacking.

Общие появления существующие: desktop y12–24px около450–700ms, mobile8–12px около400–500ms; однократно. При deep anchor/быстрой прокрутке/возврате полный контент без обязательного ожидания. Reduced motion статичен. Числа — стартовые ориентиры, разрешена настройка плавности/геометрии без смены сценария.
