### 0.1 Общая desktop-композиция и фон

- От 1024 px полноценная двухколоночная композиция Hero/кейса/контакта; горизонтальные задачи и этапы. На 1024–1199 px уменьшается внутренний декор, но не заменяется весь Hero мобильной схемой. Tablet/mobile с одной колонкой только ниже desktop-breakpoint из SPEC.
- Контент ограничен max 1200 px, но фон занимает всю ширину окна. Hero и кейс используют существующую пропорцию колонок 5/7, gap 48 px. При 1200 px полезной ширины это примерно 480 px текста + 672 px сцены. Не считать 5/7 пропорцией без учёта gap. Точный optical alignment сверяется с изображением.
- Молочная основа непрерывная. Шалфейные/лавандовые волны и мягкие световые области связывают секции; это крупные плавные формы, а не отдельный rounded gradient rectangle за каждой группой карточек. Под текстом тихие участки; границы секций не выглядят пятью несвязанными белыми страницами.
- Сохранить силуэт волн референса: воздушный фон Hero → спокойное поле задач → более заметная sage-область кейса → светлая область этапов → мягкое sage/lavender поле контакта. Фон не должен стать одинаковой локальной подсветкой в каждой секции.
- Тонкие контурные линии и редкие узлы относятся к фону/связям, не пересекают copy/CTA и не создают новый путь обработки данных. В Hero полезные связи заметнее фоновых. На mobile большая часть фонового контура убирается. В v1 фон статичен.
- Свет одинаковый: белые поверхности, мягкие тени ниже объектов, приглушённые цветовые отражения. Не добавлять chrome, neon, реалистичный прибор, коробки/полки или сферу. Образ — понятный цифровой процесс, а услуга остаётся работой Тиграна, не продуктом-платформой.
- Скругления/тени не заменяют содержимое. Композиция должна сохранять объём и смысл при отключённой анимации; фон и визуальные предметы не появляются только после запуска motion.
- Не добавлять высоту 100vh, большие пустые spacer-блоки или повышать padding ради «premium». По tokens Hero и секции имеют заданный ритм; расстояние между фактическим низом Hero и заголовком задач проверяется отдельно, не удваивается двумя случайными padding.

### 0.2 Desktop Hero: сцена, а не ряд подписей

Слева: approved надзаголовок, H1, описание, primary CTA и secondary рядом, подпись ниже. Справа — крупная предметная цифровая сцена с тремя наполненными входами и основной панелью. Шапка: бренд слева, открытые якорные ссылки, отдельный контурный Telegram справа; без общей белой капсулы. Две части визуально уравновешены: схема не маленький знак рядом с огромной колонкой текста.

```text
ТЕКСТ + ДЕЙСТВИЯ               Документы (чуть выше)
                         Сообщения             Данные
                              ╰── отдельные связи ──╯
                         Повторяющийся процесс
                       Получить → Обработать → Сохранить
```

Схема описывает расположение, не заменяет полные approved подписи шагов.

**Три входа:**

- Не три одинаковых горизонтальных pill-кнопки с иконкой и заголовком. Это компактные интерфейсные карточки с видимой внутренней структурой и разным содержимым.
- «Сообщения»: заголовок + 2–3 коротких фрагмента сообщений, небольшие маркеры/аватары; «Документы»: заголовок + 2–3 документные строки/листа; «Данные»: заголовок + небольшой фрагмент табличной структуры. Иллюстративные строки нейтральные, без новых claims, брендов клиентов, персональных данных или фиктивных метрик. Не требуется читать каждый штрих.
- Средняя карточка выше боковых, боковые слегка разноуровневые. Из референса сохраняется лёгкий статический наклон боковых карточек; не плоская ровная линейка. Заголовки остаются хорошо читаемыми.
- DRAFT ориентир: высота примерно 140–180 px на широкой сцене, а не 52–80 px; статический поворот левой -6°, средней +3°, правой +6°. Это стартовые значения для MAIN, не точное снятие геометрии референса и не утверждённые tokens. На узком desktop уменьшать угол/внутренние штрихи, не meaningful labels.

**Связи и основная панель:**

- Каждая входная карточка имеет собственную видимую изогнутую связь с основной панелью. Смысловая точка привязки на краю карточки; нельзя соединить только среднюю карточку одной вертикальной палкой, оставив остальные визуально несвязанными.
- Связи лежат за карточками, не поверх заголовков и не пересекают внутренние мини-интерфейсы. Узлы небольшие; зелёные линии тонкие, без неона. При парении точки привязки остаются соединёнными с карточками.
- Главная панель заметно шире одного входа и расположена ниже группы; небольшой статический наклон/смещение допустим по референсу, но нет необходимости делать динамический tilt. Верх: approved название «Повторяющийся процесс». Внутри три самостоятельных шага с иконками на мягких цветных подложках, стрелками и полными подписями. Это визуальный якорь, он не парит.
- Объём создают разная высота входов, перекрытие фоновых слоёв, наклоны и мягкая тень. Не перекрывать подписи карточками; не заменять это большим blur-ореолом вокруг пустого UI.
- Текст/CTA неподвижны. Approved парение ±4 px / 8 s применяется только к трём входам. Статическая композиция остаётся такой же без motion. Динамический pointer tilt остаётся NEXT STAGE / CONCEPT.

**Не принимать за соответствие desktop-референсу:** три одинаковые плитки только с названиями → одна прямая линия → плоская широкая панель внутри отдельного градиентного прямоугольника. Такой вариант передаёт базовую логику, но теряет утверждённую предметную композицию.

### 0.8 Контроль соответствия для MAIN перед новой задачей Builder

Сравнивать static desktop с references.png, а mobile — с принятым mobile-порядком. Скриншот владельца используется только как видимый пример текущего расхождения; код не изучался, причина реализации не установлена.

Это не проблема «сделать ещё шире»: надо вернуть структуру сцены.

При сверке desktop 1024 / 1280 / 1440 px проверить:

1. Три карточки Hero наполнены разными типами UI, стоят не в одной плоской линейке и каждая связана с процессом.
2. Сцена крупная, с мягкой глубиной; текст/CTA читаемы; без motion она не выглядит пустой.
3. Фон работает на ширину страницы и связывает секции, а не рисует прямоугольную рамку сцены.
4. В задачах три полноценные пары вход→результат, не только подписи/иконки.
5. Кейс сохраняет визуал ноутбука/материалов и две выходные панели; временная схема не выдана за реальный screenshot.
6. Этапы горизонтальны; контакт двухколоночный с полноценным портретом.
7. Все approved copy/tokens/ограничения сохранены; запрещённые функции из reference не возвращены.
8. Mobile-упрощения включаются только на своих ширинах; никаких растянутых mobile-плиток на desktop.

Новая визуальная сверка сначала в статике: эффект парения не исправляет неправильную композицию. Дополнительные углы/размеры DRAFT уточняет MAIN при включении раздела 0 в brief. Advisor не запускает build/browser проекта и не меняет реализацию.

## 1. Mobile — APPROVED владельцем
