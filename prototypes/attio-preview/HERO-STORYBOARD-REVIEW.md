## Композиция

Desktop: центрированный неизменённый copy; ниже два смещённых окна источников и стабильное центральное окно с шагами, полями и таблицей. Sidebar и отдельное повторяющее итог окно убраны. Документы и ответственный объединены в компактное окно. Никакого масштабирования canvas через transform:scale.

На 1440×1000 верх сцены y=497, низ подтверждения результата y=899; caption заканчивается y=953. Содержательный результат помещается на первом экране. Шрифт H1 68/72; mini-UI 14/20, вторичные подписи 12 px. Для 1024 px самостоятельная геометрия, читаемые значения и отдельное место под traffic lights.

Mobile 390 px: один общий источник с обращением, файлами и ответственным → короткая вертикальная связь → окно обработки с результатом как запись 2×2. Текст и обе CTA до сцены. От начала Hero после header до подписи — 1176 px; панель проверки MAIN в эту величину не входит. Вся desktop-сцена не уменьшается.

## Общий маршрут для связей и будущего движения

Desktop: три измеренные cubic Bézier SVG-кривые в свободном промежутке между правыми границами источников и левыми портами процессного окна. Координаты берутся из реальных DOM rect; ResizeObserver и fonts.ready обновляют только статичную геометрию. Внутри полей и таблицы декоративных путей нет.

Mobile/tablet: общий измеренный SVG-путь от нижнего порта объединённого источника к верхнему порту процесса. Внутренний короткий путь от блока полей до таблицы находится только в отведённом промежутке.

При следующем разрешённом проходе движущийся сигнал должен брать точки из **того же SVG path** через getPointAtLength; не вычислять вторую отличающуюся траекторию. В узком промежутке движется компактный сигнал, а сами значения последовательно занимают отведённые поля. Большая летящая подпись не должна пересекать содержимое окон.

## Предлагаемая последовательность motion — не реализована

1. Исходное обращение и данные остаются на местах; короткий акцент источника.
2. Последовательно выделяются стоимость, Заявка.pdf, Анна.
3. По существующим связям проходит сигнал к соответствующему порту; каждое поле заполняется своим значением и отмечается после сопоставления.
4. Из полей складывается строка №104; акцент на её добавлении, без новых данных и изменения размеров окна.
5. Появляется подтверждение «В таблице»; полный итог остаётся видимым.

Ориентир после утверждения: около 6–8 секунд для desktop, сокращённый проход по явному запуску на mobile. Это предложение последовательности, не обещание скорости услуги. Replay будущей версии использует временную презентацию поверх полного статичного состояния. При отмене / reduced motion / без JS — полный итог. Никаких новых timeline в этом проходе не подключено.

## Выполненная проверка

Разовые browser checks: 1440 / 1280 / 1024 / 768 / 430 / 390 / 360 / 320 px.

- Горизонтального скролла и обрезанного внутреннего содержимого нет.
- Геометрия сцены одинакова между всеми пятью состояниями на каждой ширине.
- Enter / Space выбирают кадры, 2px focus видим; menu открывается Enter, Escape закрывает с возвратом focus.
- Маркетинговый H1, описание и текст исходного обращения совпадают с SPEC. Manrope с кириллицей загружается.
- По 99 точкам каждого desktop SVG-пути проверено отсутствие пересечения с текстовыми rect источников, полей и таблицы. Дополнительно снимки просмотрены визуально. Заголовки окон не пересекаются с traffic lights на 1024 / 1280 / 1440 px.
- В Hero 0 активных анимаций; reduced motion оставляет полный итог. После 10 переключений нет временных clones/overlay.
- Без JS исходный HTML содержит видимый полный итог кадра 5.
- Основная CTA открывает сохранённый контакт исходного прототипа. Telegram-логика и шаблоны не изменены, повторная проверка внешнего composer не входила в этот проход.
- Ошибок страницы и консоли не обнаружено.
